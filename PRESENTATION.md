# МТС EnergyTool — ИИ-консультант
### Презентация решения · True Tech Hack&Change 2026

---

## 1. Проблема

Клиент приходит на сайт с бытовой формулировкой: «счёт вырос», «хотим солнечные панели»,
«нужно навести порядок в учёте». Он не знает, какой продукт ему нужен, а менеджер тратит
время на первичный квалификационный диалог.

**Что нужно бизнесу:**
- довести клиента от свободного описания задачи до конкретного продукта;
- не выдумывать факты и не давать обещаний, которых компания не выполнит;
- собрать параметры объекта и контакты для расчёта;
- сохранить контекст диалога для менеджера.

---

## 2. Решение

ИИ-консультант на сайте МТС EnergyTool, который:

1. понимает задачу своими словами;
2. задаёт только недостающие уточняющие вопросы;
3. подбирает одно из пяти направлений;
4. отвечает строго по базе знаний;
5. честно отказывается, если данных нет;
6. собирает заявку и передаёт менеджеру резюме диалога.

**Пять направлений:** облачный учёт, поиск коммерческих потерь, распознавание показаний
по фото, солнечные станции, выход на оптовый рынок.

---

## 3. Демо-сценарий

**Клиент:** «У нас завод в Московской области, хотим солнечную станцию».

**Консультант:** объясняет состав проекта и диапазон 15–500 кВт, спрашивает, что важнее —
снизить платёж или иметь резерв.

**Клиент:** «Мощность 450 кВт, потребление 60 000 кВт·ч в месяц».

**Консультант:** уточняет профиль потребления и кровлю, объясняет разницу сетевой и
гибридной станции.

**Клиент:** «Кровля плоская, цель — снизить платёж».

**Консультант:** предлагает сетевую станцию, учитывает пригрузочную систему и предлагает
заявку. В форме — ФИО, телефон, компания. Менеджер получает резюме: объект, регион,
мощность, потребление, кровля, цель, продукт и что уточнить на звонке.

---

## 4. Архитектура

```
Браузер: чат + debug + история + форма заявки
        │  JSON /api/chat, /api/lead, /api/sessions
FastAPI ── consultant.py ── тема, слоты, момент заявки
        ├─ summary.py ───── резюме для менеджера
        ├─ store.py ─────── SQLite: сессии, сообщения, заявки
        └─ energy_rag.py ── ЯДРО (общее с solution.py)
              BM25 + bge-m3 → RRF → Qwen3 Reranker → контекст + правила продукта
              → Qwen3.8-27B (без размышлений) → очистка ответа
                 │
        19 Markdown-документов базы знаний
```

Одно ядро для веб-чата и конкурсного `solution.py`: качество на лидерборде = качество в чате.

---

## 5. Гибридный RAG

- Фрагмент = раздел Markdown с путём заголовков («Солнечные станции → Размещение»);
  длинные разделы режутся по абзацам с перекрытием.
- BM25 со стеммингом и словарём бытовых синонимов («симки» ↔ SIM, «проверите учёт» ↔ аудит).
- Плотный поиск BAAI/bge-m3: эмбеддинги базы считаются один раз и кэшируются.
- Четыре ранжирования (BM25/dense × последняя реплика/весь диалог) сливаются RRF —
  уточнения вроде «А сколько стоит?» понимаются в контексте диалога.
- Qwen3 Reranker 8B выбирает 8 лучших из 24 кандидатов.
- Любой компонент необязателен: при сбое — деградация до BM25, а не ошибка.

---

## 6. Защита от галлюцинаций

- Факты — только из контекста; системный промпт запрещает знания «от себя».
- Для продуктов из выдачи в промпт автоматически добавляются разделы базы
  «Факты, которые можно утверждать» и «Чего утверждать нельзя».
- Нет факта в базе или вопрос вне компетенции — прямой отказ и предложение специалиста.
- Индикативные цифры — только с оговорками; без итоговой стоимости, гарантий экономии,
  имён клиентов и производителей.

---

## 7. Диалог и заявка

- Слоты: тип объекта, регион, мощность, потребление, кровля, приборы, ценовая категория,
  цели, почасовые данные.
- Нормализация: «сорок» → 40, регионы — в читаемые названия, цены — по категориям.
- Уточнения не повторяются: если клиент уже ответил, вопрос снимается.
- Заявка предлагается, когда параметров достаточно или клиент сам просит специалиста.
- Резюме собирается из слотов и истории; контакты не выдумываются.
- История сохраняется для всех диалогов, включая те, что закончились без заявки.

---

## 8. Интерфейс

- Светлый лендинг в стиле МТС: красный, графит, тёплый белый.
- Тёмный чат-виджет с быстрыми ответами.
- Режим отладки: время ответа, режим ответа и поиска, тема, слоты, модель, источники с оценками.
- История диалогов с отметкой «заявка».
- Новый диалог — полный сброс контекста.
- Адаптив для планшета и телефона; без сборки и JS-фреймворков.

---

## 9. Конкурсный сабмит

`solution.py` читает `questions.csv` и `knowledge-base.zip`, пишет `submission.csv` (`id,answer`).

- Тот же движок `energy_rag.py`, что в веб-прототипе; встроенные диалоги разбираются на реплики.
- Формат ответа под эталон: прямой ответ → факты с оговорками → один уточняющий вопрос.
- Параллельная обработка, ограниченные повторы при 429/5xx, общий дедлайн 1000 с.
- Валидный `submission.csv` существует с первой секунды и обновляется по ходу.
- `submission.zip`: `solution.py`, `energy_rag.py`, `requirements.txt` (только `httpx`).

## 10. Результат и развитие

**Сделано:** рабочий веб-прототип, конкурсный `solution.py`, Docker, README,
презентация, 18/18 демо-вопросов с непустыми ответами, проверенные сценарии заявки
и истории.

**Эффект:** менеджер получает квалифицированный лид и резюме, клиент — быстрый ответ
без ожидания и без навязанных обещаний.

**Дальше:** CRM-интеграция, авторизация менеджера, Postgres и очередь, A/B-оценка
ответов, автоматический контроль запрещённых утверждений, расширение базы знаний.
