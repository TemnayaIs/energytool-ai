## Почему v0.1 проигрывала baseline (< 0,5)

- Курируемые ответы на демо-вопросы перекрывали LLM: на новых вопросах «правила» срабатывали
  по случайным словам и давали ответ не на тот вопрос.
- Qwen3 по умолчанию «размышляет»: при ограниченном MAX_TOKENS ответ мог оказаться пустым
  и заменялся экстрактивным fallback — в логах это не было видно.
- Только BM25: бытовые формулировки («проверите учёт» ↔ «аудит», «расширить» ↔ «наращивать»)
  не находили нужный раздел. Эмбеддинги и реранкер платформы не использовались.
- Жёсткое усечение ответа обрезало финальный уточняющий вопрос.

## v0.2 — что изменено

1. Гибридный поиск: BM25 + bge-m3 (по последней реплике и по всему диалогу), RRF, Qwen3 Reranker.
2. В контекст автоматически добавляются «правила продукта» (что можно / нельзя утверждать).
3. Режим размышлений Qwen3 выключен (`chat_template_kwargs.enable_thinking=false`, с fallback
   на `/no_think`), теги `<think>` вычищаются.
4. Промпт под формат эталона: прямой ответ → факты с оговорками → один уточняющий вопрос,
   40–90 слов; few-shot из демо-ответов.
5. Никаких курируемых ответов в сабмите — все вопросы идут через RAG + LLM.
6. Общий дедлайн 1000 с, заглушка submission.csv с первых секунд, ограниченные повторы.

## Идеи для следующих сабмитов (по одному фактору)

- TOP_K 8 → 12 (больше контекста) или 6 (точнее).
- Включить проверку ответа вторым вызовом (самопроверка по контексту) — если хватает времени.
- Убрать few-shot (проверить, не копирует ли модель шаблон слишком буквально).
