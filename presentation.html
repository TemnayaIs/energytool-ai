МТС EnergyTool — ИИ-консультант для сайта

Трек AI от МТС · True Tech Hack&Change 2026 · Первый тур

Репозиторий: https://github.com/TemnayaIs/energytool-ai

Задача

Разработать ИИ-консультанта, который помогает клиентам МТС EnergyTool разобраться в вопросах энергопотребления: снизить расходы на электроэнергию, наладить учёт энергоресурсов и выявить потери.

Что умеет решение

  • RAG: поиск по базе знаний (BM25 + bge-m3 + Qwen3 Reranker)
  • Отвечает понятным языком, подбирает продукты EnergyTool
  • Задаёт уточняющие вопросы, корректно отказывает при недостатке информации
  • Собирает заявку для менеджера (имя, телефон, компания)
  • Многошаговый диалог, сброс контекста, режим отладки, история сессий

Архитектура

Веб-прототип (app/)

  • FastAPI + SQLite + статический фронтенд
  • Сессии, сообщения, заявки (leads)
  • Контекстно-зависимая эскалация на менеджера
  • Режим отладки (источники, latency, intent)

RAG (energy_rag.py)

  • BM25 + bge-m3 (dense) → RRF → Qwen3 Reranker 8B
  • Qwen3.8-27B (thinking mode) для генерации
  • Курируемые ответы (answers_core.py) + extractive fallback
  • Self-check отключён (ухудшал стиль)

Как работает RAG

  • Чанкинг: Markdown → разделы → фрагменты ~1600 символов, overlap 240
  • BM25: лексический поиск + синонимы (АСКУЭ, УСПД, ПУ, тарифы)
  • Dense: bge-m3 эмбеддинги, косинусное сходство
  • RRF: слияние ранжирований (веса BM25 1.0, dense 1.3)
  • Reranker: Qwen3-Reranker-8B, топ-24 кандидата → топ-8
  • Контекст: 11000 символов + guard-блоки (ограничения по продукту)

Генерация ответа

  • Qwen3.8-27B с reasoning (thinking mode)
  • Температура 0.0, детерминированный вывод
  • Структура: продукт → 2–3 факта → уточняющий вопрос
  • Курируемые ответы для частых вопросов (детерминированные)
  • Extractive fallback при сбое LLM

Контекстно-зависимая эскалация на менеджера

Форма контактов показывается не по таймеру, а по контексту диалога:

  • Вопросы про цену/договор/оформление → сразу форма
  • Сложные/многопродуктовые сценарии → форма
  • Критичные слоты (регион, мощность, тип объекта) не заполнены после 4 ходов → форма
  • Safety net: после 5 ходов без заявки

Настраиваемые параметры: LEAD_TURN_THRESHOLD, LEAD_PRICE_MARKERS, LEAD_COMPLEXITY_MARKERS, LEAD_MISSING_SLOT_INTENTS.

Сбор заявки

  • Форма: имя, телефон, компания, согласие
  • Резюме диалога для менеджера (LLM или fallback)
  • Сохранение в SQLite, доступ через API
  • История сессий сохраняется, доступна для проверки

Технические детали

  • Запуск: python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
  • Docker: docker compose up --build
  • Сабмит: python scripts/build_submission.py → submission.zip
  • Тесты: python tests/smoke_solution.py (1000/1000 OK)
  • Ограничения соблюдены: ≤150 слов, refusal при отсутствии информации, только из базы знаний, без секретов в коде
  • Данные: только предоставленная база знаний, тестовые данные для демо
