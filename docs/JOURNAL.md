### Как устроена v6b

- **База знаний** режется по разделам Markdown; у каждого фрагмента в индексе путь заголовков
  («Солнечные станции → Размещение»).
- **Поиск**: BM25 (стемминг + словарь бытовых синонимов) и эмбеддинги bge-m3 — по последней реплике
  и по всему диалогу, слияние RRF; Qwen3-Reranker (12 кандидатов × 800 символов, запрос в формате
  из документации vLLM) голосует вместе с гибридным поиском, а не заменяет его.
- **Промпт**: роль консультанта, прямой ответ → 1–2 факта с оговоркой → один уточняющий вопрос,
  35–70 слов; в контекст добавляются «правила продукта» (разделы «Факты, которые можно утверждать /
  Чего утверждать нельзя») и список «что уточнять у клиента»; 4 похожих примера «вопрос → эталон»
  из `examples.py` (демо + 82 наших вопроса).
- **Работа с моделью**: `chat_template_kwargs.enable_thinking=false`, `max_tokens ≥ 2048`; если ответ
  пустой из-за размышлений (finish_reason=length) — повтор с утроенным лимитом и `/no_think`.
- **Надёжность**: ограниченные повторы при 429/5xx, контроль дедлайна (1000 с), заглушка
  `submission.csv` с первых секунд.

### Главные выводы дня

1. **Рывок 35 → 58.6 дала не «умность» промпта, а работа с моделью на прокси.** Прокси, похоже,
   игнорирует отключение размышлений; размышления входят в `max_tokens` (подтвердили на вебинаре),
   ответ обрезался и подменялся вырезкой из базы. Фикс — запас токенов и повтор.
2. **Правки промпта после v6b балл не подняли.** Длиннее (−1.7), «одна мысль» + правила вебинара (−3.1).
   Возможна и обратная причина — разброс оценки платформы (пока не измерен, см. идеи).
3. **Локальный судья (Qwen IQ3) не различает версии ближе ~0.1.** Тот же код v5 против самого себя
   дал 0.455. Значит, локально ловим только ошибки и крупные изменения; тонкую настройку проверяем
   на платформе.
4. **Размышления на вопросах с числами** локально эффекта не дали, а прогон в 2.2 раза дольше.
5. **Эмбеддинги локально** подключены (Ollama bge-m3), заметного эффекта на нашем наборе нет.
6. **Заготовленные ответы под демо-вопросы — вредны** (v0.1): на новых вопросах срабатывают не к месту.
7. Организаторы (вебинар): на private идёт **лучший публичный сабмит**; разбивки по вопросам нет;
   модель судьи не раскрывается; сабмиты за день сгорают в 00:00 МСК.

### Инфраструктура, которая появилась

- `eval/run_eval.py` — генерация ответов, прогон любого ZIP «как на платформе», имитация простого
  бейзлайна (`--set PIPELINE=base`), судья по методике регламента.
- `eval/runner.py` — очередь прогонов (`eval/queue/*.job`), чтобы ставить тесты удалённо.
- `eval/extra_questions.csv` / `extra_golden.csv` — 82 своих вопроса с эталонами по базе
  (пороги мощности, провокации, вне компетенции, диалоги с заявкой).
- `tests/mock_proxy.py`, `tests/smoke_solution.py` — проверка сабмита без доступа к API
  (в т.ч. 429, обрезанные размышления, отказ прокси от параметров).
- Веб-приложение (`app/`) использует то же ядро; отладка показывает режим поиска и источники.

### Идеи на 13.11 (5 попыток)

1. **Измерить разброс платформы**: загрузить v6b ещё раз без изменений. Если балл «гуляет» на 2–3
   пункта, то long/v8 могли проиграть случайно, и выводы вечера надо пересмотреть.
2. **Размышления осознанно**: судя по времени прогона (730–850 с), на платформе модель и так часто
   размышляет. Вариант: сразу дать большой бюджет (`max_tokens` 6000), без пустой первой попытки —
   ответы стабильнее, время то же или меньше.
3. **nofs** (`leaderboard/submission_v06b_nofs.zip`) — нужны ли подобранные примеры.
4. **Подбор примеров по эмбеддингам** вместо BM25 — точнее похожие примеры для стиля ответа.
5. **Больше контекста**: соседние фрагменты того же раздела для топ-результатов (мелкие фрагменты
   ~500 символов могут резать ключевой факт).
6. Промпт v6b больше не трогать без серьёзной причины: две попытки его улучшить ухудшили балл.
